프로젝트 회고록

이번 클라이언트 개발 과정은 단순히 화면을 구현하는 수준을 넘어, 실제 사용자 경험을 고려한 흐름을 만드는 데 집중했다.
초기에는 API 연동과 상태 관리에서 시행착오가 있었지만, 점차 구조를 정리하면서 데이터 흐름과 UI 업데이트가 자연스럽게 이어지도록 개선할 수 있었다.

특히 기억에 남는 부분은 다음과 같다:

상태 관리 정리
처음에는 로컬 상태만 사용하다 보니 컴포넌트 간 데이터 전달이 불편했다. 이후 전역 상태 관리와 훅을 적용하면서 데이터 일관성을 유지할 수 있었고, 불필요한 리렌더링도 줄일 수 있었다.

에러 처리와 사용자 피드백
단순히 오류 메시지를 띄우는 대신, 상황에 맞는 안내 UI를 보여주도록 개선했다. 이를 통해 사용자가 어디서 문제가 생겼는지 직관적으로 이해할 수 있게 했다.

UI/UX 개선
실제 사용 시 불편할 수 있는 부분(예: 버튼 위치, 모달 닫기 흐름 등)을 여러 차례 수정했다. 사용자의 클릭 동선이나 시각적 집중도를 고려해 레이아웃을 다듬으면서 완성도가 높아졌다.

이번 프로젝트를 통해 배운 점은 기능 구현보다 중요한 것은 흐름의 완성도라는 것이다.
앞으로는 더 빠르게 구조를 잡고, 초기에 사용자 여정을 구체적으로 설계한 뒤 개발에 들어가는 습관을 들이고 싶다.
